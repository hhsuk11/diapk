# DB 구조 초안

이 전환 프로젝트의 DB는 `경기 장부`를 원본으로 삼고, 랭킹/통계는 장부에서 만들 수 있는 결과로 분리합니다. Google Sheet처럼 여러 시트가 동시에 진실을 갖는 구조를 피하기 위한 설계입니다.

## 핵심 테이블

| 테이블 | 역할 |
| --- | --- |
| `seasons` | 시즌 상태를 관리합니다. `DRAFT`, `OPEN`, `CLOSED` 중 하나이며, 종료 시즌은 변경하지 않습니다. |
| `scoring_rule_versions` | 시즌 시작 전에 선택되는 MMR 규칙 버전입니다. 시즌 중 변경하지 않습니다. |
| `players` | 리그 참가자 ID를 정규화해서 저장합니다. 기존 Sheet의 `ID`와 경기 이력 이름의 기준입니다. |
| `player_characters` | 참가자별 직업 캐릭터명을 보관합니다. `사용자목록`의 드루/어쎄/네크/슴딘 캐릭터명이 여기에 들어갑니다. |
| `games` | 모든 경기의 원장입니다. 새 UUID를 기본키로 쓰고, 승리팀, 스코어, 일시, 상태, 레거시 경기 ID와 원본 행 번호를 보관합니다. |
| `game_players` | 경기별 4:4 참가자, 팀 슬롯, 경기 당시 직업입니다. |
| `rating_events` | 경기 적용 후 참가자별 점수 변동 내역입니다. 열린 시즌 재계산의 기준입니다. |
| `season_player_stats` | 시즌별 랭킹, 점수, 종합 승패, 티어 요약입니다. 종료 시즌은 스냅샷으로 보존합니다. |
| `season_player_class_stats` | 시즌별 참가자의 직업별 승패 요약입니다. |
| `admin_users` | Google OAuth 도입 후 관리자 계정입니다. |
| `permission_grants` | 운영자별 세부 권한입니다. |
| `audit_logs` | 경기 입력, 취소, 복구, 권한 변경 같은 관리자 작업 이력입니다. |

## 시즌 정책

- 기존 Sheet에서 가져오는 시즌은 `CLOSED`와 `is_imported_snapshot=true`로 둡니다.
- 종료 시즌의 `games`는 조회용이며 취소/복구 대상이 아닙니다.
- 신규 시즌은 `DRAFT`에서 MMR 규칙 버전을 선택한 뒤 `OPEN`으로 시작합니다.
- `OPEN` 시즌의 MMR 규칙 버전은 변경하지 않습니다.

## 취소와 복구

- 경기 삭제는 하지 않습니다.
- 취소 시 `games.status=CANCELED`, `canceled_at`, `cancel_reason`을 기록합니다.
- 복구 시 `games.status=ACTIVE`, `restored_at`을 기록합니다.
- 두 작업 모두 `audit_logs`에 남깁니다.
- 점수는 열린 시즌에서 해당 경기 이후의 `ACTIVE` 게임만 시간순으로 다시 적용해서 재계산합니다.

## 이관 원칙

- `전적이력`은 경기 원장 후보로 사용합니다.
- 레거시 경기 ID는 중복될 수 있으므로 유니크 키로 쓰지 않습니다. 원본 Excel 행 번호와 새 UUID로 각 경기를 구분합니다.
- `전적확인`, `전적확인_시즌*`, `포인트변동`, `듀오전적`은 검증 및 스냅샷 이관에 사용합니다.
- Excel의 Google 전용 함수는 배포 로직으로 쓰지 않고, 필요한 규칙만 Python 서비스 코드로 옮깁니다.
