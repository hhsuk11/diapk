# 구현 결정 기록

## 인증과 권한

- 일반 사용자는 로그인 없이 공개 조회 화면을 사용한다.
- 개발/초기 내부 테스트에서는 `AUTH_MODE=dev`로 모든 관리자 권한을 부여한다.
- 운영 전환 시에는 Google OAuth를 사용한다.
- Super 관리자는 운영자에게 세부 권한을 부여할 수 있다.
- 기본 권한은 `game:create`, `game:cancel`, `game:restore`, `mmr:manage`, `season:manage`, `admin:manage`로 나눈다.

## 시즌과 MMR

- 기존 시즌은 이관 후 `CLOSED` 상태로 고정한다.
- 종료 시즌의 경기 취소/복구는 허용하지 않는다.
- 신규 시즌은 시작 전에 MMR 규칙 버전을 선택해야 한다.
- 시즌 진행 중 MMR 규칙 변경은 허용하지 않는다.
- 초기 점수, 배치 경기 수, K 값 등은 규칙 버전의 설정값으로 보관한다.

## 경기 입력과 취소

- Discord 연동은 1차 범위에서 제외한다.
- 관리자는 팀짜기 결과 화면 또는 수동 입력 화면에서 승리팀과 스코어를 입력한다.
- 열린 시즌의 모든 게임은 취소 및 복구 가능하다.
- 취소/복구는 삭제가 아니라 `ACTIVE`와 `CANCELED` 상태 전환으로 처리한다.
- 상태 전환은 감사 로그에 누가, 언제, 왜 수행했는지 남긴다.
- 점수 재계산은 열린 시즌의 해당 경기 이후 게임을 시간순으로 재생하는 방식으로 구현한다.

## 팀짜기와 진행중 게임 표시

- 팀짜기는 친선/임시 조합 용도로도 사용할 수 있으므로 등록되지 않은 닉네임 입력을 허용한다.
- 공식 게임 등록과 결과 등록은 등록된 플레이어만 허용한다.
- 팀짜기에서 게임을 등록하면 서버에 `진행중 게임` 상태를 저장하고, 메인 화면은 새로고침 없이 이를 표시해야 한다.
- 1차 구현은 OCI 프리티어와 Docker 운영 단순성을 우선해 5초 주기 polling으로 진행중 게임 상태를 조회한다.
- 동시 접속자나 실시간성이 더 중요해지는 시점에는 같은 상태 API를 SSE(Server-Sent Events)로 확장한다.
